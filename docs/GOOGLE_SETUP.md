# Fix the Google Calendar API setup

The reported screenshot identifies an API-disabled error. The owning Google Cloud project, its current settings and Render's deployed commit have not been inspected. These are steps for the account owner; no production changes or OAuth grants were made in this task.

1. In the Render dashboard, open the service serving `bmt-calendar.onrender.com` and inspect its existing `GOOGLE_CLIENT_ID` environment value. Compare it locally in the next step. Do not change it or reveal the client secret.
2. Open [Google Cloud's OAuth clients](https://console.cloud.google.com/auth/clients), choose the candidate project in the top project selector, and open the existing web client. Its **full client ID** must match Render's `GOOGLE_CLIENT_ID`. If it does not, inspect the other projects you can access until it matches. Do not create a replacement client. “Borka Tax Planning App” is a useful clue, but the exact ID is the check. Google documents the [Clients location](https://developers.google.com/workspace/guides/create-credentials).
3. Record that project's **project ID and project number**. “My First Project” alone does not identify it: Google project names need not be unique, while project IDs and numbers are unique. If the API error names a project number, compare that too. See [Google's project identifiers](https://docs.cloud.google.com/resource-manager/docs/creating-managing-projects).
4. Keep that same project selected. Open **APIs & Services → Library**, search **Google Calendar API**, open it and click **Enable**. The service is `calendar-json.googleapis.com`. You can use [Google's Workspace API library](https://console.cloud.google.com/apis/library/browse?filter=category%3Agsuite); Google's [enablement instructions](https://developers.google.com/workspace/guides/enable-apis) also include a Calendar-specific link. If it is already enabled, confirm the client/project match again. If you lack permission to enable it, the project administrator must perform this step.
5. Wait until the console finishes enabling it and shows it enabled. Allow a few minutes before retesting if the app initially reports the old error; this is a practical retry interval, not a guaranteed propagation time.
6. Return to [BMT Calendar settings](https://bmt-calendar.onrender.com/app/settings), then choose **Calendar connections → Google Calendar → Check connection**. API enablement itself should not require a new OAuth grant. Check the same Google account that owns the appointments.
7. Only if the check still reports missing permissions or invalid authorization, use **Reconnect**, select the same Google account, and approve both Calendar permissions: availability (`calendar.freebusy`) and event access (`calendar.events`). Then run **Check connection** again. The scope meanings are in [Google's Calendar authorization documentation](https://developers.google.com/workspace/calendar/api/auth). If a disabled-API error remains, revisit the project/client match; repeated reconnects do not enable an API.
8. Open the exact public test page: [Boris Musheyev — Discovery Call](https://bmt-calendar.onrender.com/book/boris-musheyev/discovery-call). Choose an otherwise available future working day and verify that availability loads without the Google error. Do not submit a real booking for this check; an empty working day can also result from busy time, notice, horizon or schedule rules.

If reconnect instead reports a redirect mismatch, inspect the existing client's authorized redirect URIs. The Calendar callback is exactly `https://bmt-calendar.onrender.com/api/google/callback`. Preserve the Borka application's existing callbacks. Creating credentials, replacing secrets, changing consent audience and removing grants are not part of this API-enable repair.

Successful connection and availability checks resolve the reported setup blocker; they do not publish the local code changes or prove live invitation/email delivery. The finalized feature branch still needs review and explicit approval for publication/deployment, a production backup/migration rehearsal, and separately authorized live acceptance checks described in [the launch checklist](LAUNCH_CHECKLIST.md).
